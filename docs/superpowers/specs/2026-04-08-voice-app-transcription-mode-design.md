# Voice App 转录模式与胶囊交互设计

## 背景

`voice-app/` 当前已经具备以下能力：

1. Rust + Tauri 多窗口桌面壳
2. 豆包流式 ASR 链路
3. OpenAI-compatible LLM 与 MCP 工具链
4. 全局热键长按录音、中断重启和结果窗口控制
5. 极简状态胶囊样式

当前状态胶囊的实际表现是：

1. 胶囊内部只显示状态 icon 和波形 bars
2. 不显示任何可见 ASR 文本
3. overlay 窗口固定在屏幕底部居中

用户本阶段已经明确：

1. 不做 caret 旁气泡方案，因为要兼容 macOS
2. 继续保留底部极简胶囊作为唯一实时 UI
3. 需要区分 `agent 模式` 与 `转录模式`
4. 转录模式中，ASR 文本要显示在胶囊内部
5. 转录模式中，一旦识别到文字，bars 就隐藏，只显示文字
6. 转录模式停止时，不做流式插入，而是在最终识别完成后一次性插入到当前输入光标处
7. 转录模式支持静音自动停止，并提供设置项，默认 `3500ms`

本设计文档的目标，是为 `voice-app` 引入一套明确的 **双模式热键语义 + 转录胶囊文本显示 + 单击提交输入** 方案，并约束其 UI、状态机和实现边界。

## 问题与目标

当前链路存在以下问题：

1. `agent 模式` 与“听写输入”语义混在同一条语音链路里
2. 用户无法从交互入口上明确区分“这是在跟 AI 对话”还是“这是在做直接转录输入”
3. 如果后续采用流式直接插入文本，会带来回滚、误写和跨应用兼容风险
4. 当前胶囊只适合表达状态，不足以支撑转录预览

本阶段目标：

1. 增加显式的 `转录模式`
2. 为 `agent 模式` 与 `转录模式` 定义不同的单击语义
3. 在转录模式下，胶囊内部显示 ASR 识别文本
4. 文本长度驱动胶囊宽度变化，但设置最大宽度
5. 识别出文本后，胶囊隐藏 bars，只保留文字主视图
6. 停止时等待最终识别完成，再一次性输出到当前焦点输入位置
7. 将静音自动停止做成设置项

## 非目标

本阶段不做：

1. 不实现 caret 锚点气泡
2. 不实现转录过程中的流式文本插入
3. 不在这一轮实现已插入文本的回滚
4. 不修改 agent 模式的 LLM / MCP 主链
5. 不重做当前胶囊的视觉语言
6. 不将结果窗口强行复用于转录预览

## 结论

采用以下路线：

**保留当前底部胶囊作为统一 runtime UI，通过热键手势显式切分 `agent 模式` 与 `转录模式`。转录模式下在胶囊内部显示 ASR 文本，单击或静音超时只负责“停止并提交”，最终文本在 ASR 完成后一次性插入当前焦点。**

关键决定：

1. `agent 模式` 保持当前极简状态胶囊，不显示 ASR 文本
2. `转录模式` 由独立热键手势进入
3. 转录模式中，开始阶段显示状态 icon + bars
4. 一旦 `transcript` 非空，bars 隐藏，胶囊改为文本视图
5. 文本视图宽度随文本长度增长，但受 `max-width` 限制
6. 超过最大宽度后，优先显示尾部内容
7. `单击` 在转录模式中表示“停止并提交”
8. `单击` 在 agent 模式中仍表示“中断 / 关闭当前对话”
9. `静音自动停止` 做成设置项，默认 `3500ms`
10. 转录模式结束后不弹结果窗，默认直接回到待命

## 交互设计

### 1. 模式语义

#### `agent 模式`

用于：

1. ASR -> LLM -> 工具 / MCP
2. 普通语音对话
3. 需要模型理解、改写、总结、调用工具的场景

交互约束：

1. 继续使用现有长按语义
2. 保持当前状态胶囊
3. `单击` 仍表示中断当前识别、生成或关闭当前结果

#### `转录模式`

用于：

1. 直接把语音转成文字
2. 最终将识别结果输出到当前系统焦点输入位置

交互约束：

1. 通过独立热键手势进入
2. 进入后立即开始录音和 ASR
3. 识别过程中只在胶囊内部显示文本预览，不写入输入框
4. `单击` 表示停止并提交
5. `静音超时` 也表示停止并提交

### 2. 热键行为

本阶段推荐语义如下：

1. `长按`：进入 `agent 模式`
2. `双击`：进入 `转录模式`
3. `单击`：
   - 在 `agent 模式` 中：中断 / 关闭当前对话
   - 在 `转录模式` 中：停止并提交

说明：

1. 不再追求“单击在所有模式下语义一致”
2. 单击行为必须依赖当前模式解释
3. 模式差异必须在状态机中成为一等状态，而不是前端猜测

### 3. 转录模式胶囊行为

转录模式视觉分为两个阶段：

#### 阶段 A：尚未识别出文字

显示：

1. 状态 icon
2. bars 波形

此阶段不显示文本。

#### 阶段 B：已识别出文字

显示：

1. 状态 icon
2. 文本预览

此阶段：

1. 隐藏 bars
2. 文本成为唯一主视觉内容
3. 胶囊宽度可随文本增长

### 4. 文本显示规则

转录模式文本显示采用以下规则：

1. 单行显示
2. 文本区域优先显示**尾部内容**
3. 胶囊有最小宽度和最大宽度
4. 宽度增长只发生在 `min-width ~ max-width` 区间内
5. 超出最大宽度后不再继续拉长，而是截断前部，保留最近识别的文本

推荐视觉策略：

1. `min-width` 保持当前满意的紧凑基线
2. `max-width` 约束在 `420px ~ 520px`
3. 文本区域占据主体空间
4. 状态 icon 保持小尺寸，不抢文本视觉重心

## 运行时状态设计

建议在现有 runtime 语义上增加显式输入模式：

1. `Agent`
2. `Transcription`

并在热键状态机或 `AppState` 中持有当前轮模式信息。

### 转录模式的核心状态

建议最小状态如下：

1. `Idle`
2. `TranscriptionListeningEmpty`
3. `TranscriptionListeningText`
4. `TranscriptionStopping`
5. `TranscriptionInserting`

状态语义：

#### `TranscriptionListeningEmpty`

1. 已进入转录模式
2. 正在录音
3. 胶囊显示 bars
4. `transcript` 为空

#### `TranscriptionListeningText`

1. 已进入转录模式
2. 正在录音
3. 胶囊显示文本
4. bars 已隐藏

#### `TranscriptionStopping`

1. 已收到 `单击` 或静音超时
2. 麦克风采集已停止
3. 正在等待 ASR 最终 `Completed`
4. 胶囊应保持可见，避免用户误以为任务已结束

#### `TranscriptionInserting`

1. 已拿到最终 transcript
2. 正在向当前焦点输入位置执行一次性插入
3. 插入完成后直接回到 `Idle`

## 数据流设计

### 1. Agent 模式

保持当前链路：

```text
hotkey
  -> start listening
  -> ASR Completed
  -> LLM generation
  -> local tool / MCP / result
```

### 2. 转录模式

采用以下链路：

```text
double click
  -> enter transcription mode
  -> start listening
  -> Partial / Final updates transcript preview
  -> single click or silence timeout
  -> stop capture
  -> commit ASR session
  -> wait for Completed
  -> type_text(final transcript)
  -> hide overlay
  -> return idle
```

关键约束：

1. `Partial / Final` 只更新胶囊预览
2. 识别过程中不向输入框输出任何文字
3. 只有 `Completed` 之后才允许真正插入文本

## ASR 事件处理

当前桌面端对：

1. `Partial`
2. `Final`
3. `Completed`

还没有做模式化分流。

本阶段建议：

### Agent 模式

1. `Partial / Final` 仅用于内部 transcript 状态维护
2. `Completed` 继续走现有 `ASR -> LLM`

### 转录模式

1. `Partial / Final` 更新胶囊内部文本
2. 当文本从空变为非空时，切换到“文本视图”
3. `Completed` 不进入 LLM，直接走本地 `type_text`

## 设置设计

新增转录模式设置项：

1. `transcription_silence_timeout_ms`

要求：

1. 默认值：`3500`
2. 允许范围：`500 ~ 5000`
3. 可选支持 `0 = 禁用自动停止`

设置页文案建议：

1. 标签：`转录静音自动结束`
2. 提示：`转录模式中，持续静音超过该时长后会自动停止并提交。`

## 窗口与 UI 约束

本阶段继续复用现有 overlay 窗口，不新增新的 runtime 窗口类型。

明确约束：

1. 不新增 caret 气泡
2. 不新增跟随光标窗口
3. overlay 仍然固定在屏幕底部区域
4. 视觉变化由胶囊内部布局完成

实现建议：

1. overlay 外层透明窗口可适当增大，避免频繁动态 resize Tauri 窗口
2. 实际胶囊宽度在透明窗口内部动态变化
3. 胶囊内容视图根据模式和 transcript 长度切换

## 错误处理

必须明确处理以下情况：

1. 转录模式下单击停止后，ASR `Completed` 为空
2. 插入文本失败
3. 静音自动停止触发时，任务已经被手动停止
4. 在 `TranscriptionStopping` 阶段再次收到热键事件

处理原则：

1. 转录模式失败时进入可见错误态
2. 不写入半成品文本
3. 不弹 agent 结果窗
4. 错误信息进入 runtime logs

## 测试策略

### Rust / 状态机测试

至少覆盖：

1. `双击` 进入转录模式
2. 转录模式下 transcript 为空时显示 bars 状态
3. transcript 非空后切换为文本视图
4. 转录模式下 `单击` 触发停止并提交
5. `Completed` 后直接走 `type_text`
6. 转录模式不会触发 LLM generation
7. agent 模式下 `单击` 仍然是中断 / 关闭结果
8. 静音超时会触发与单击相同的停止提交逻辑

### 前端测试

至少覆盖：

1. overlay 在 agent 模式下只显示状态 icon 和 bars
2. overlay 在转录模式且 transcript 为空时显示 bars
3. overlay 在转录模式且 transcript 非空时隐藏 bars、显示文本
4. 文本超长时宽度受限且显示尾部内容

### 交互 smoke

至少验证：

1. 双击进入转录模式
2. 转录过程中出现文本后，bars 消失
3. 单击后停止并提交
4. 最终文字进入当前输入框
5. 提交后胶囊自动关闭
6. agent 模式原有中断行为不回归

## 验收标准

本设计被认为满足需求，需要同时满足：

1. `agent 模式` 与 `转录模式` 在热键语义上明确分离
2. 转录模式中胶囊内部显示实时 ASR 文本
3. 一旦识别到文字，bars 不再显示
4. 胶囊宽度可随文本增长，但受到最大宽度约束
5. 转录模式中 `单击` 表示停止并提交
6. 转录模式完成后最终文本被一次性输出到当前焦点
7. agent 模式中的 `单击` 仍保持原有中断 / 关闭语义
8. `静音自动停止` 支持设置项，默认 `3500ms`
