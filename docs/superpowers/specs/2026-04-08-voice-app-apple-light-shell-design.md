# Voice App Apple Light Shell 设计

## 背景

`voice-app` 当前已经具备完整的桌面语音运行链路，但 `voice-app/apps/desktop` 的主窗口仍然保留较强的控制台感和卡片堆叠感。用户这一轮的诉求不是补功能，而是把整套桌面界面往 `voice-app/DESIGN.md` 的 Apple 参考方向收拢，同时保留桌面应用的左右工作台结构。

本轮设计过程中，用户已经明确否定了以下方向：

1. 不要网页式 marketing hero，不要 `Speak to your desktop.` 这类首页宣传标题
2. 不要强烈的黑白对冲，不要左深右浅的割裂布局
3. 不要卡片墙，不要大量漂浮面板
4. 不要为了像官网而牺牲桌面工作台结构

本轮最终确认的方向是：

1. 主窗口维持左导航 / 右内容的桌面结构
2. 左右两边进入同一套浅色体系，只保留轻微层差
3. 整体尽量靠近 Apple Light Mode，而不是 Apple 官网黑白发布页
4. 右侧内容区要有更清楚的 section 分割，但分割方式以分区、分隔线和轻层差为主，而不是退回大卡片
5. `overlay` 使用 `Smoky Graphite` 深石墨半透明胶囊
6. `result` 使用浅色 sheet / panel

## 目标

本轮只解决主 app 的视觉系统、信息层级和布局组织问题：

1. 将主窗口统一为 Apple 风格的浅色桌面壳层
2. 保留左导航 / 右内容结构，不改成网页首页布局
3. 取消首页营销式主视觉，改成直接进入运行控制
4. 减少卡片感，用 grouped section、分隔线和轻底色差替代漂浮卡片
5. 让 `History / Settings / Logs` 跟首页统一到同一套视觉语言
6. 让 `overlay / result` 与主窗口同属一套产品语言，但保留各自适合的材质差异

## 硬约束

1. 不改 runtime、history、settings、logs 的业务语义
2. 不改 Tauri 命令接口、数据结构和设置 schema
3. 不改四个主面板的入口名称与可达性
4. `overlay` 仍然是系统浮层，不与主窗口完全同材质
5. `result` 仍然是独立结果窗口，不并回主窗口
6. 视觉改造允许重排信息层级，但不允许改变核心操作路径

## 非目标

本阶段不做：

1. 不新增功能入口
2. 不修改录音、识别、生成、工具执行的状态机
3. 不改变历史记录、设置、日志的数据来源和行为
4. 不引入新的全局状态管理方案
5. 不引入新的设计依赖或 UI 组件库

## 设计结论

### 1. 全局视觉系统

主窗口统一采用 Apple Light Mode 语义：

1. 页面主背景以 `#f5f5f7` 为基准，允许使用非常轻的灰白渐变，但不使用彩色渐变、纹理或炫光
2. 文字主色使用 `#1d1d1f`
3. 交互强调色只使用 `#0071e3`
4. 左右两边共享同一套浅灰阶，左侧导航只比右侧内容区略深一层
5. 阴影收敛为少量软阴影，只用于整体窗口壳层、overlay 和少数浮起元素，不把所有内容都做成浮卡

### 2. 布局系统

主窗口保留桌面工作台结构，但去掉强烈分栏对冲：

1. 左侧仍为固定导航区
2. 右侧仍为主要内容区
3. 左右两区颜色和材质统一，不再出现“大块深色侧栏 + 大块浅色内容”的强反差
4. 右侧内容区通过 section 带、横向分隔线、局部纵向分隔线和标题层级来切分信息
5. 分段强调优先级为：
   - section 级分区
   - 横向分隔线
   - 轻底色带
   - 局部纵向分隔线
   - 极少量面板或 sheet

### 3. 首页 `Runtime`

首页不再是展示页，而是运行控制工作台。

#### 顶部运行控制区

首页顶部使用独立 section 带，直接展示：

1. 当前阶段
2. `开始录音 / 结束录音`
3. 一句简短状态说明
4. 麦克风、MCP、权限等关键状态摘要

约束：

1. 不出现营销标题
2. 不出现全宽黑色 hero
3. 不把运行控制包成一张重卡片
4. 通过 section 带和标题层级表达它是“第一优先级区域”

#### 中段运行内容区

运行数据区明确分成左右两栏：

1. 左栏：实时文本、任务结果
2. 右栏：系统摘要

并通过中间纵向分隔线表达两者职责不同。

实时文本与任务结果虽然同属左栏，但仍是两个独立内容组，通过横向分隔线和小标题区分。

系统摘要不再做四张独立卡片，而改成一组连续条目，每项包含：

1. 小标签
2. 主值
3. 一行说明
4. 必要时的轻链接动作

### 4. 历史记录 `History`

历史页采用列表优先、少卡片化的 grouped layout：

1. 顶部只保留筛选和统计
2. 列表项之间通过分隔线和少量空白区分
3. 识别文本、任务结果、时间和状态都放回列表语义中表达
4. 状态强调依赖文字和轻视觉提示，而不是高饱和色块
5. `预览`、`重新生成` 保持存在，但按钮风格收敛为 Apple Light Mode 语言

### 5. 设置 `Settings`

设置页改成更接近系统设置的 grouped form：

1. 不使用多层深色面板
2. 每个设置分组作为连续 section 出现
3. 字段之间通过细分隔线和一致的输入控件风格组织
4. 输入框、下拉、文本域和按钮都使用浅色底和轻描边
5. 错误、警告、成功反馈保留，但只作为提示，不主导页面气氛

### 6. 日志 `Logs`

日志页采用浅色开发者工具页语义：

1. 顶部保留等级筛选、关键字、导出、清空和统计
2. 日志内容以连续列表组织，不使用深色终端底
3. 信息和错误通过标签、文字层级和轻强调区分
4. 错误态允许有更明确的标识，但不做大面积高饱和警示块

### 7. Overlay

`overlay` 采用独立于主窗口的 `Smoky Graphite` 材质：

1. 深石墨半透明底
2. 柔和描边
3. 轻模糊和软阴影
4. 简洁 icon + 文本布局

原因：

1. `overlay` 是系统级浮层，本来就应该与主窗口有材质区分
2. 当主窗口转为统一浅色后，深石墨胶囊更能建立浮层识别感

### 8. Result Window

`result` 使用浅色 sheet / panel：

1. 顶部保留关闭按钮
2. 下方通过两段明确分区表达“识别内容”和“执行结果”
3. 通过横向分隔线切分语义，而不是把内容堆在单一容器里
4. 视觉目标是易读、安静、独立，而不是主界面的缩略卡片

## 组件规则

### 1. 导航

1. 左侧导航区为浅灰背景
2. 当前选中项允许使用更白一点的底和更深一点的文字
3. 非选中项只用文字层级区分
4. 不使用夸张的光效或大面积渐变

### 2. 按钮

1. 主按钮使用 `#0071e3`
2. 次按钮使用浅底 + 轻描边
3. 所有主要动作按钮继续使用偏胶囊的圆角
4. 不新增第二种强调色

### 3. 内容分段

1. section 之间必须有清晰的标题层级和上下留白
2. section 内部优先使用分隔线，不优先使用卡片
3. 必须让用户一眼识别“运行控制区 / 运行数据区 / 其他页面预览区”这三层结构

## 测试影响

以下测试意图需要保留，但断言文本或结构可能需要更新：

1. 默认打开首页
2. 四个主面板可以切换
3. runtime 诊断信息可正常渲染
4. 设置字段可正常渲染和编辑
5. overlay 和 result 仍按窗口类型渲染

4. `result` 的容器层次

## 验收标准

满足以下条件才算本轮设计被正确实现：

1. 主窗口整体为统一浅色体系
2. 左导航 / 右内容结构仍然保留
3. 左右颜色只保留轻微层差，不再强烈割裂
4. 首页顶部不再出现营销 hero 和宣传文案
5. 右侧内容区存在明确的 section 分割
6. 首页、历史、设置、日志都明显减少卡片墙感
7. `overlay` 使用 `Smoky Graphite` 深石墨胶囊
8. `result` 使用浅色 sheet / panel
9. 所有交互强调色仍然统一为 Apple Blue
10. 与本轮 UI 重构直接相关的测试完成更新并运行
