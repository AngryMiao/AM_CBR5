# Voice App Quiet Console Shell 设计

## 背景

`voice-app/apps/desktop` 当前已经具备完整的桌面语音运行链路，但主窗口仍偏向深色玻璃态与卡片堆叠。用户本轮要求不是补功能，而是把首页、设置、历史、日志四个页面统一改成更简洁、更实用的浅色科技桌面工作台，并明确要求保留左右布局、右侧滚动，以及现有录音识别胶囊和结果返回卡片。

在本轮设计确认过程中，用户已经明确锁定以下方向：

1. 整体视觉采用 `Quiet Console` 路线，浅色、科技、克制、信息密度略高
2. 禁止退回重卡片化设计
3. 首页、历史、日志使用单页连续分组
4. 设置页使用页内顶部 tabs，底部固定保存栏
5. 主窗口增加自定义顶部拖动栏，并与整体视觉统一
6. 不修改 `overlay` 录音识别胶囊和 `result` 返回卡片

## 目标

本轮只解决主窗口壳层、标题栏和四个主页面的视觉系统与信息组织问题：

1. 将主窗口重构为浅色科技控制台壳层
2. 保留左导航 / 右内容结构与桌面应用语义
3. 首页改成运行控制工作台，而不是展示页或 hero 首页
4. 历史和日志改成 grouped list / console list，而不是卡片列表
5. 设置页改成顶部 tabs + 底部固定保存栏
6. 用 `shadcn/ui` 现有组件重组交互控件与页面结构
7. 增加自定义顶部拖动栏和窗口控制按钮，使主窗口具备更完整的桌面端表达

## 硬约束

1. 不修改 `OverlayWindow.tsx` 和 `ResultWindow.tsx` 的结构与视觉目标
2. 不修改录音识别胶囊和结果返回卡片
3. 不修改 runtime、history、settings、logs 的业务语义和核心操作路径
4. 不修改 Tauri 命令接口、设置 schema、历史/日志/诊断数据结构
5. 不引入新的 UI 依赖，复用现有 `src/components/ui/*`
6. 保留左侧主导航与四个面板入口名称
7. 主窗口右侧继续保持独立滚动

## 非目标

本阶段不做：

1. 不新增首页快捷操作中心
2. 不新增全局搜索、命令面板或二级导航体系
3. 不改 overlay / result 窗口的视觉语言
4. 不改变语音状态机、识别流程、MCP 运行链路
5. 不改历史记录、日志、设置的底层持久化逻辑

## 设计结论

### 1. 全局视觉系统

主窗口统一采用浅色科技控制台语言，而不是深色 glassmorphism：

1. 主背景基于冷灰白渐变，强调“桌面工具”而不是“营销页”
2. 文字主色使用深灰蓝系，避免纯黑对比过硬
3. 强调色保留为低面积蓝色，仅用于激活态、焦点态和关键状态
4. 页面层级主要由留白、细分隔线、轻底色差与字重建立
5. 只有少数区域允许弱容器感，不允许整页回到 card wall

### 2. 主窗口壳层

主窗口将从“系统默认标题栏 + 页面内容”重构为“自定义顶部标题栏 + 左右工作区”：

1. 顶部新增一条自定义 titlebar
2. titlebar 左侧为品牌区
3. titlebar 中间为页面名、状态文案与主拖拽区
4. titlebar 右侧为窗口控制按钮（最小化 / 最大化切换 / 关闭）
5. 下方仍然是左导航 / 右内容双栏结构

titlebar 的视觉目标是：

1. 更像浅色桌面工具条，而不是浏览器 tab bar
2. 与左侧导航和右侧内容形成一体化壳层
3. 薄、安静、克制，不抢占内容区注意力

### 3. 左侧导航

左侧导航保持一级面板切换，但改为更线性的桌面控制台表达：

1. 选中项使用浅底 + 细描边 + 左侧细高亮条
2. 未选中项以文字层级和轻 hover 表达
3. 品牌区不再使用重渐变 logo 块
4. 页脚保留 ready / runtime note，但收敛为细信息条

### 4. 首页 `Runtime`

首页改成三段式运行工作台，对应 `RuntimeStatus.tsx`：

#### 顶部运行控制带

展示当前最关键的运行信息：

1. 当前模式
2. 当前页面标题与运行说明
3. 平台、麦克风、MCP 数量等关键摘要
4. 必要的轻量状态徽标

约束：

1. 不出现 marketing hero
2. 不出现“开始录音 / 结束录音”这类已移除入口
3. 不再用四张 summary cards 表达状态

#### 中段主工作区

采用 `主栏 + 侧栏` 结构：

1. 主栏放任务结果、实时摘要、权限提醒
2. 侧栏放系统摘要清单
3. 通过纵向分隔线表达两栏职责差异

#### 底段次级诊断区

把详细诊断下沉到页面下方：

1. MCP runtime
2. 工具列表
3. AngryMiao 运行时
4. 同步失败或系统错误提示

### 5. 设置 `Settings`

设置页采用顶部 tabs + 底部固定保存栏：

1. tabs 固定在内容顶部
2. 底部固定保存栏固定在视口底部
3. 中间表单内容区随 tabs 切换

tabs 划分如下：

1. `通用`
2. `快捷键`
3. `ASR`
4. `模型`
5. `MCP`

表单视觉规则：

1. 使用 grouped form，而不是堆叠卡片
2. 字段之间主要靠 section 标题、说明和分隔线组织
3. 输入框、下拉、开关、文本域统一采用浅底、细描边、圆角一致的控件系统
4. 错误、警告、成功反馈继续保留，但集中收敛到字段下方与底部保存栏

底部固定保存栏必须同时承载：

1. 当前保存状态
2. 运行前置条件警告或保存反馈
3. `重置`
4. `保存设置`

### 6. 历史 `History`

历史页从卡片列表重构为连续任务流：

1. 顶部保留搜索与状态筛选
2. 顶部保留完成数 / 失败数摘要
3. 列表项改为 grouped row
4. 每条记录按“任务编号与状态 -> 识别文本 -> 任务结果 -> 详情与操作”展开
5. 操作按钮 `预览 / 重新生成` 保持存在，但风格收敛为轻量工具按钮

目标是让用户更像在读任务流，而不是一张张翻卡片。

### 7. 日志 `Logs`

日志页改成浅色 console list：

1. 顶部保留级别筛选、关键字、导出、清空
2. 顶部展示当前显示条数与级别统计
3. 每条日志作为连续 row 展示
4. 错误态通过细色条、badge 与文字层级表达
5. 不使用深色终端背景，不使用大面积高饱和错误块

### 8. `shadcn/ui` 使用方式

本轮不会为了组件而组件，而是借助现有 `src/components/ui/*` 统一交互与控件表达：

1. 壳层与结构：`ScrollArea`、`Separator`
2. 导航与状态：`Button`、`Badge`
3. 设置页：`Tabs`、`Input`、`Textarea`、`Select`、`Switch`、`Button`
4. 历史与日志：`Input`、`Select`、`Badge`、`Button`

不再依赖 `Card` 作为页面主要组织手段。

## 交互与实现边界

### 1. 自定义标题栏

主窗口允许切换为自定义标题栏方案：

1. `main` 窗口关闭系统默认装饰
2. 顶部使用前端自定义 titlebar
3. 中间区域可拖拽
4. 交互元素区域不可拖拽
5. 窗口按钮由前端调用 Tauri window API 实现

### 2. 不变部分

以下部分只允许做适配，不允许做视觉目标变更：

1. `OverlayWindow.tsx`
2. `ResultWindow.tsx`
3. 录音识别胶囊
4. 结果返回卡片

## 测试影响

以下测试意图需要保留：

1. 默认打开首页
2. 左侧四个主面板仍可切换
3. 首页仍渲染 runtime / platform / MCP / AngryMiao 相关信息
4. 设置字段仍可渲染、编辑、保存、重置、校验
5. 历史记录的查询、预览、重试仍正常
6. 日志的筛选、导出、清空仍正常
7. overlay / result 仍按窗口类型渲染

以下断言预计需要更新：

1. 主窗口壳层和标题栏结构
2. 首页由卡片转为分区式结构后的 DOM
3. 设置页 tabs 和固定保存栏
4. 历史、日志的 grouped row 结构

## 验收标准

满足以下条件才算本轮设计实现正确：

1. 主窗口整体切换为浅色科技控制台风格
2. 自定义顶部拖动栏已落地，并与页面壳层统一
3. 左导航 / 右内容结构仍然保留
4. 首页、历史、日志明显减少卡片墙感
5. 设置页变为顶部 tabs + 底部固定保存栏
6. 所有原有业务交互链路保持可用
7. `overlay` 胶囊和 `result` 返回卡片未被改动
8. 与本轮改动直接相关的测试完成更新并运行
